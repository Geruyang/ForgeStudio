## 1. 项目一句话与基本信息

**一句话**：一个人指挥多个 AI Agent（Codex CLI、Trae、ZCode 三代开发环境，五工作包并行分工），在约 5 天内（2026-10-13 方案定稿，10-14 13:11 开工计时）从零设计并交付了一个 **Windows 桌面端"工程 Agent 工作台"**——把 Claude Code / Codex 式的 AI 编程助手做成可安装的原生客户端，核心差异化是**任务验收单 + 与源码/固件版本绑定的交付证据 + 软件与实机硬件统一闭环**，并真实打通了 STM32 与 ZYNQ 两款硬件板卡的实机验证。

## 2. 项目背景与动机（为什么做）

用户核心诉求（出自任务书"必须保留的用户要求"节，为用户原话整理）：

1. 要一个类似 Claude Code / Codex 的 Agent 平台，**同时服务通用软件开发和嵌入式工程**——市面上的 AI 编程工具面向纯软件，嵌入式"构建→烧录→串口验证"链路没有一等公民支持。
2. 必须是**可安装的 Windows 桌面客户端**，不交付网页、不接受只有界面/假数据/演示的原型。
3. 明确**不参考 OpenCode**（用户否决了一条旧 fork 路线）；以 Codex 的项目/任务/会话/审阅体验为主参考，借鉴 Claude Code 的计划/权限确认/干预体验，用自有品牌与实现。
4. 技术路线锁定：**Electron + React + TypeScript + Codex app-server + 自研本机工程 MCP/执行器**。
5. **48 小时内交付**，按 T1（必达）/T2（依赖硬件）/T3（可顺延）分级验收，受限交付不得冒充全范围完成。
6. 核心差异化（产品创新的落点）：**任务验收单、与源码/固件版本绑定的证据、软件与实机统一交付**——即"AI 做完了"必须由机器可判的验收与证据链背书，而不是模型自己说"完成了"。

前期资产（2026-10-11～13，`agent-design` 仓库）：先行完成了 34 个开源仓库下载核查、667 个 Agent 技能的逐项审核适配、16 本地 + 4 远端 MCP 的安装联通，以及对 Codex app-server 协议（stdio JSONL、审批语义、generate-ts 类型生成）、Claude Agent SDK、probe-rs 烧录能力的**在线事实核查**，产出《项目方案 v2.1》《任务书评审与交接报告》（含 7 项 P0 勘误补丁，如 MCP 默认 60s 超时会杀掉烧录操作、`CODEX_HOME` 隔离机制等）与《笔记本实施任务书》。这一阶段把"48 小时开工后不踩坑"的地基打完。

## 4. 技术架构

### 4.1 主线（ForgeStudio，npm workspaces monorepo）

```text
ForgeDesk-zcode/
├── apps/desktop/            Electron 44 应用
│   ├── src/main/            主进程：engine-host（引擎生命周期/预热/provider 切换重建）、
│   │                        runner-host（utilityProcess 拉起执行器）、ipc-registry（50+ 通道白名单）、
│   │                        auto-updater、ssh-credentials、security、provider-config
│   ├── src/preload/         contextBridge 白名单桥（OpResult 解包）
│   ├── src/bridge/          MCP 桥（ForgeDesk.exe + ELECTRON_RUN_AS_NODE=1 复用随包 Electron 当 Node 运行时）
│   └── src/renderer/        React 19 + zustand（85 模块：会话流/审批卡/diff 面板/工程面板/设置…）
├── packages/
│   ├── contracts/           冻结契约（zod）+ codex app-server generate-ts 生成的 743 个协议类型
│   ├── engine-adapter/      Codex app-server stdio JSONL 适配（新旧两组审批协议映射、代次配对、
│   │                        auth 语义、provider extraEnv、模型切换重建线程）
│   ├── engineering-mcp/     MCP stdio 服务：七工具（inspect/build/test/package/verify/list…）桥到 runner
│   └── engineering-runner/  唯一权威工程执行器：状态机/操作幂等(requestKey)/A·B 级证据快照/
│                            node:sqlite(WAL) 存储/HTTP 控制面(loopback+Bearer)/设备适配/SSH 远程传输
├── engineering/             profiles / acceptance 模板 / fixtures（标注"模拟"）
├── tools/vendored/codex/    锁定版 Codex CLI 0.162.1（SHA-256 记录，随包分发）
└── scripts/                 smoke-runner（13 步）/ gui-walkthrough（CDP 走查）/ model-task-e2e /
                             uia-task-wizard / cdp-probe 等自动化验收脚本
```

关键技术决策（DECISIONS 摘要）：
- **进程模型**：单一权威执行器 = Electron 主进程 `utilityProcess.fork` 拉起 runner 服务；MCP 桥经 loopback HTTP（随机端口 + 随机 Bearer Token + 发现文件）代理到同一实例，桥重启不产生第二个设备所有者。
- **引擎隔离**：子进程显式 `CODEX_HOME=<产品数据目录>\engine`，绝不读写用户既有 Codex/Claude 配置；不复制既有客户端凭证。
- **存储**：Node ≥22.5 内建 `node:sqlite`（WAL + 迁移记录），零原生 ABI 重编负担；日志/固件放文件、库内只存引用与哈希。
- **证据分级**：A 级 = 工作区指纹（git commit/diff 或内容清单回退，输入变化→证据过期→验收不点亮）；B 级 = 任务专属内容寻址快照（构建/验收从快照执行、产物独立归档）。防作弊红线：**验收项 passed 只能由执行器点亮**，模型无法通过"回复完成"通过验收。
- **依赖锁定**：Electron 44.7.2 / React 19.3.0 / Vite 8.3.4 / esbuild 0.28.2 / electron-builder 26.15.3 / serialport 13（N-API）/ zod / vitest 5。
- **构建管线**：esbuild 四产物（main ESM / preload·bridge·runner CJS）；NSIS per-user 打包；runner 依赖闭包自包含（独立 npm install + 6 关键模块强校验）。

### 4.2 并行线（ForgeDesk-codex，独立第二实现）

同一任务书下的第二条完整实现（也验证了方案的鲁棒性）：Electron + 分包结构 + 227 个测试文件；独有贡献为**原生授权烧录 UI 关卡**（原生确认框核对板卡/探针/UID）、**受限实机模型线程**（hardware-agent 仅暴露六个固定工具、空参数、主机决定目标/请求键）、**第二 Windows 账户隔离验收**、Keil `-j0` 后台编译流程、ZYNQ FZ3B 板端构建/部署/推理恢复语义。两线在硬件矩阵上互补：A 线打通 STM32（SWD 烧录链），B 线打通 ZYNQ（SSH 远程执行链）。

### 4.3 质量与验收工程（两线共同的特色）

- **安装态验证关口**：每个版本必须过"构建 → SHA-256 → 静默安装 → 13 步安装态冒烟（真实构建/验收/幂等/证据过期/导出/MCP 握手）→ GUI 自动化走查（CDP 点真实按钮，36 断言）"才算交付；
- **GUI 自动化**：自研 CDP 走查脚本（含 React 19 受控输入的原型 setter 键盘级事件驱动经验）与 UIA 实操脚本（截图存档 ui-audit/）；
- **模型驱动 E2E**（model-task-e2e）：真实模型 token 消耗的端到端验收——模型修复缺陷 → 独立核验 → MCP 留证 → 人工验收 → 导出；
- **多轮筛查**：静态扫描 → 逐文件代码审查 → 运行时审计 → 深度四层审查，共修复 13+ 项实际缺陷，每轮全门复验。

## 6. 成果意义

1. **产品意义**：验证了"AI 编程助手 + 工程验收证据链 + 嵌入式实机闭环"融合的桌面产品形态——模型不能自证完成，必须留下机器可判的构建/测试/烧录/串口证据；这在 AI 辅助开发工具中是差异化创新点（任务书 §核心差异化由用户定义）。
2. **方法论意义**：完整实践了"一人指挥多 Agent 并行开发"的工程范式——五工作包契约冻结分工、双实现线冗余竞赛、三代开发环境无缝迁移（Codex/Trae/ZCode）、48 小时分级验收交付；同时全程贯彻"不虚报"原则（fixture 标注模拟、未知保持未知），为 AI 协作开发建立了可审计的信任基线。
3. **技术资产**：Codex app-server 协议适配层（含新旧审批协议、elicitation 转产品审批卡）、SSH 远程执行传输、A/B 级证据快照、CDP GUI 自动化走查框架、多厂商模型接入层——均为可复用的技术组件。
