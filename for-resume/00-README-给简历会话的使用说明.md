## 使用建议（给简历会话）

1. **先读 01 再读 02**：01 给出项目全貌与可量化指标；02 回答"哪些决策是用户本人做出的"。
2. **项目名建议**：对外可称"ForgeStudio —— Windows 工程 Agent 桌面平台（个人项目）"。用户以"一人 + 多 AI Agent 团队"的模式完成，这在简历中本身就是核心亮点（AI 协作工程能力），建议正面呈现而非隐藏。
3. **可引用的硬指标**（详见 01 §5）：约 3.7 万行源码/测试、双实现线并行、6 家模型提供方接入、2 款真实硬件板卡的实机闭环、13 步安装态冒烟 + 36 断言 GUI 自动化走查全绿、v21 正式安装包（NSIS，SHA-256 可查）。
4. **诚实边界**：项目文档全程执行"不虚报"原则（fixture 必须标注模拟、未验证保持未验证）。简历措辞请沿用相同口径：实机验证过的才写"实机验证"，模拟的写"fixture 验证"。02 的"边界与不宜声称项"一节列出了具体清单。
5. **本总结的局限**：Trae 阶段（2026-10-14～16）的聊天原文存于 Trae 云端，本地不可恢复；该阶段用户指令以项目内 `docs/DECISIONS.md`（D9–D17 明确引用用户指令原文）与 `docs/PROJECT_STATE.md` 为准，可信度高但非逐字全量。Codex 阶段与 ZCode 阶段为逐字提取（分别来自 Codex 会话日志与 ZCode 本地 SQLite 会话库）。
