# 安装与使用指南（Install Guide）

> QA（Agent D）维护。安装、模型配置、环境检查、设备绑定与故障恢复（任务书 §15.3 交付项：
> "安装、模型配置、环境检查、设备绑定与故障恢复说明"）。

## 1. 安装

1. 获取安装包 `ForgeDesk-Setup-<版本>.exe`（NSIS per-user）与其 SHA-256（随交付清单发布，建议先校验）；
2. 双击安装。**安装包未签名**：Windows SmartScreen 可能弹出"Windows 已保护你的电脑"——选"更多信息 → 仍要运行"（预期行为，见支持矩阵 §3）；
3. 安装为 per-user（无需管理员权限）；数据目录为 `%APPDATA%\ForgeDesk\`；
4. **共存隔离**：产品引擎使用独立 `CODEX_HOME=%APPDATA%\ForgeDesk\engine`，不读取、不写入你现有的
   `%USERPROFILE%\.codex` 或其他 Codex/Claude 客户端配置；卸载/升级不影响用户现有配置；
5. 首次启动后进入"环境检查"（见 §3）。

> 开发态（仓库内）：`npm install` → `npm run dev`。数据在 `<repo>/.runtime/`。

## 2. 模型配置（二选一）

模型凭证**只**存于产品数据目录（`%APPDATA%\ForgeDesk\engine`），不进用户主目录、不进导出包。

| 方式 | 步骤 | 说明 |
|---|---|---|
| API key | 设置 → 模型配置 → 粘贴 API key（`sk-...`）→ 保存 | 产品把 key 写入产品专属 CODEX_HOME 的凭证存储；诊断/导出界面永不回显完整 key |
| ChatGPT 账号登录 | 设置 → 模型配置 → 登录 | 在产品内嵌流程完成账号登录（需联网）；登录态同样隔离在产品 CODEX_HOME |

配置后：模型选择面板列出真实可用模型（来自引擎 `model/list`）；认证状态显示 `api_key` 或
`chatgpt_account`。**未配置时**认证状态为 `none`（ok=false）——产品不虚报"已就绪"，模型驱动的
软件任务不可发起（工程面板驱动的构建/测试/证据不受影响）。

## 3. 环境检查（诊断面板）

设置 → 诊断（或任务面板顶部"诊断"入口）。各字段含义：

| 字段 | 含义 | 异常时怎么办 |
|---|---|---|
| `runnerVersion` | 工程执行器版本 | 与应用版本不一致 → 重启应用 |
| `uptimeMs` | 执行器运行时长 | — |
| `storagePath` / `storageOk` | 证据存储目录与可写性 | false → 检查磁盘/权限；此时验收判定不可信 |
| `gitAvailable` | 是否检测到 git | false 属可选缺失：A 级证据走完整输入清单内容摘要（hasGit=false 标明），不影响使用 |
| `probeRsAvailable` / `probeRsPath` | probe-rs 是否可用及路径 | T2 前提；false → 安装 probe-rs 后重启应用（设备烧录/验证不可用，软件任务不受影响） |
| `serialPortsAvailable` | 串口子系统是否可用 | T2 前提；false → 检查驱动 |
| `activeDeviceLock` | 当前持锁的任务（设备独占） | 非空表示有任务占用设备；其他任务会等待/被拒（M8） |
| `pendingAuthorizations` | 待授权设备操作数 | >0 → 到"设备授权"卡片处理 |
| `lastError` | 最近一次错误摘要（中文优先，含日志引用） | 按提示排障；"导出诊断"提供完整包（**不含任何凭证**） |

## 4. 设备绑定流程（T2）

1. **首次确认目标**：连接板卡后，设备面板枚举 USB 身份（VID/PID/探针序列号）。首次绑定必须
   **人工确认**目标设备（目视板卡与身份一致）；
2. **绑定**：确认后创建设备绑定（`dev-` 永久 ID，禁止用 COM 号等易变值充当身份）；
3. **授权语义**：
   - 引擎审批 ≠ 设备授权：模型会话里的 `accept/acceptForSession` **不能**替代设备操作授权；
   - `device.flash` 前由执行器核验用户授权，范围 = **指定设备 + 产物 sha256 + 任务范围**；
   - 授权范围变化（换产物/换设备/换任务）须**重新确认**；
   - 所有操作带 requestKey 去重：重复点击/重发返回原操作，不重复烧录（M7）。

## 5. 故障恢复

### 5.1 引擎重启 / 引擎退出（M3）
- 现象：会话中断，状态显示真实（stopped/error），不显示伪成功；
- 恢复：重新发起回合即可。历史缺口（未闭合回合）在恢复视图中标"不完整"，产品**不伪造**缺失消息；
- 引擎重启后旧审批待办自动失效：旧 requestId 的应答被拒绝（不把旧批准重放给新连接）。

### 5.2 审批丢失（M2）
- 现象：审批卡片因引擎重启/窗口重载而失配；
- 恢复：失配待办不可应答（拒绝或标失效），由模型在**新回合**重新发起审批；用户应答永远绑定
  当前连接代次的 requestId；
- 未知请求（查无此 requestId）的应答被拒绝并提示，不静默挂起。

### 5.3 unknown 操作（烧录中崩溃/断连，M9）
- 现象：烧录操作状态 `unknown`（调用超时不证明外部动作停止）；
- 恢复：**不自动重烧**。按提示先核验设备（读回校验/串口身份 buildId 比对），确认板上固件与
  预期产物哈希后，再决定重新烧录；核验通过前该操作不计为成功。

### 5.4 证据过期（M5）
- 现象：任务输入（未提交修改/未跟踪文件/配置）在验证后发生变化 → 证据标 stale，已点亮的
  "通过"不再显示为通过；
- 恢复：重新运行对应验收（build/test）生成绑定当前输入指纹的新证据；输入不再变化后通过恢复；
- A 级声明：证据绑定当前工作区状态，可检测模型可写范围内的输入变化，**不构成防篡改保证**。

### 5.5 其他
- MCP 超时/桥接断连：操作按预算收尾并落 unknown/failed，可安全重试（requestKey 去重防重复副作用）；
- 存储/诊断导出：永远不含 API key/令牌（导出前请放心，仍建议导出包不公开传播）。

## 6. 常见问题

- **SmartScreen 告警？** 未签名安装包的预期行为（§1）。
- **诊断显示 gitAvailable=false？** 可选依赖，不影响软件任务；A 级证据自动切换为内容摘要模式。
- **"需要人工确认"卡住？** 验收单中 `manualRequired` 项需你在面板上手动确认（模型不能代确认）。
