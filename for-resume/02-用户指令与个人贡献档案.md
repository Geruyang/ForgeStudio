## 1. 用户角色的总体定位

在本项目中，人类用户不是"旁观者"也不是纯"打字员"，而是承担了以下七种角色（按简历价值排序）：

1. **产品负责人 / 需求定义者**——定义产品形态、差异化与验收红线；
2. **技术路线决策者**——选定与否决技术方案；
3. **多 Agent 组织架构师**——设计"主会话统一指挥 + 子 Agent 按复杂度并行"的分工模型，并在三条开发环境间迁移指挥；
4. **资源与凭证提供者**——6 家模型 API key/订阅、2 套硬件板卡+探针、Vivado Enterprise 许可证、第二 Windows 账户、2 个自研开源 GitHub 工程作为验证载体；
5. **实机 QA 测试员**——以真实用户身份实测产品，多条指令直接倒逼出深层缺陷修复；
6. **关键取舍与授权决策点**——范围裁剪（什么暂缓/什么推进）、安全授权边界（管理员权限、默认口令、睡眠期间自主执行）；
7. **物理世界执行者**——亲手完成烧录授权确认、第二账户切换操作、许可证导入、报错回传等 Agent 无法替代的动作。

## 3. 哪些是用户自己想出来的（高置信原创清单）

供简历会话直接引用的个人决策/原创点：

1. **产品概念与差异化**："任务验收单 + 版本绑定证据 + 软硬件统一交付"的 AI 工程工作台；拒绝网页/假原型/演示形态；否决 OpenCode 参考路线。
2. **多 Agent 组织模型**：主会话统一指挥接受人类指令、子 Agent 按任务复杂度分配模型与思考强度、并行加速——此指令在 Codex 线开工第一条（DEV-U001）即由用户给出，并成为两线共同的工程宪法。
3. **双线并行策略**：同一任务书同时驱动 Codex 与 Trae 两条独立实现线（各自目录隔离），后期再迁移 ZCode 接力——用户全程以"输出只放 XX 文件夹"的指令维持三线资产边界。
4. **模型配额调度规则**：用量低于 5% 暂停子 Agent 等待恢复（资源约束下的吞吐管理）。
5. **关键 UX/工程改进**：烧录进度条、Keil 后台编译、"认证即可选模型"（无需先选目录/开会话）、设置页与整体界面优化、产品更名 ForgeStudio。
6. **质量方法论**："全面测试不要放过任何细节 + 操纵电脑实操验证"、"3 轮 bug 筛查 + 优化"、"继续审查不能放过任何细节"、"你要检查潜在的其他错误，别让我一次又一次尝试"（把 Agent 从单点修复推向系统性自查）。
7. **资源编排**：接入两块板卡并指派验证路线（STM32→A线/GestureScreen；FZ3B→两线/fz3b-semantic-video-search 均为用户自研开源工程）、四家模型 key、Vivado 许可、第二 Windows 账户、默认口令授权与"睡眠期免询问执行"的授权设计。
8. **优先级取舍**：STM32 实机暂缓（ZCode 线）、第二用户验收暂缓、时间校准暂缓——每次范围收缩均由用户明示而非 Agent 自行放弃。

## 5. 边界与不宜声称项（保持项目"不虚报"口径）

- 安装包**未代码签名**（SmartScreen 可能告警）；Windows 10/ARM64 未验证。
- 主线（zcode 线）的 STM32/probe-rs SWD 烧录路径未实机执行（按用户指示暂缓），主线实机验证走 **FZ3B/ZYNQ SSH 远程执行**；STM32 SWD 实机验收由**并行 codex 线**完成。简历表述两线成果时应分开陈述。
- 设备适配的探针/串口部分在主线为 fixture 验证（49 测试，标注模拟）；"受控自主设备操作"未宣称，设备操作走引擎审批之外的独立授权。
- A 级证据是工作区指纹，不构成防篡改保证（文档已如实声明）。
- 代码主体由 AI Agent 编写；用户的贡献是**产品定义、架构与路线决策、组织与流程设计、资源供给、实机验证与质量把关**（本档案 §1 七角色），简历建议按此定位，避免"逐行手写代码"式的误导表述。
